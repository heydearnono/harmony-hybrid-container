# 2026-09-02 目标变更：从纯调研转向真实鸿蒙基座

## 问题

用户明确了预期：**要一个真实的鸿蒙基座，整个项目用 AI 开发**。

这与仓库此前的定位冲突。`CLAUDE.md` 写的是「当前阶段：纯调研」「不擅自在 `harmony/` 下生成半成品工程」，
`README.md` 写的是「**不是**一个待交付的 App 工程」。目标变更后这些约定需要改。

更重要的是：「真实」意味着**必须能编译**。没有工具链，`docs/` 里所有代码片段永远停在「未编译验证」，
「AI 开发鸿蒙」这件事就只是纸面推演。所以工具链从「可选实验」变成**关键路径**。

## 检索路径与原始发现

`experiments/001` 原设计的第一个动作是全局 `npm install -g @deveco/deveco-cli`。
查元信息时发现该包有 `postinstall` 钩子（`node scripts/postinstall.mjs`），即安装即执行代码；
而 npm 元信息里 `repository` / `homepage` / `bugs` / `author` **四个字段全缺**，maintainers 是三个个人邮箱账号。
因此改为 **`npm pack` 下载 tarball 离线解包审读**，不安装不执行。

这个绕行带来了本轮全部关键发现（详见 `experiments/001-deveco-cli-无IDE可行性/README.md` 步 0.5）：

1. **`postinstall` 无害**，且文件头有 `Copyright (c) 2026 Huawei Device Co., Ltd.`，补上了包内 provenance 证据。
2. **官方文档的环境变量名写错了**：文档 Linux 一节写 `DEVECO_CLI_CLI_PATH`，包内 `SKILL.md` 实际是
   **`DEVECO_CLI_CLT_PATH`**（CLT = Command Line Tools），且表述通用、无平台限定。
3. **`create` 与 `build` 都没有 DevEco Studio 硬依赖**；Studio 只卡 `check lint`（≥6.0.0）、`ui`（≥6.1.0）、
   `run --apply`（≥6.1.1）、`check compat`。
4. **包内自带完整 Empty Ability 模板 25 个文件**，离线可用——真实基座的官方来源就在这里。
5. 包内有 `SKILL.md`，华为把 DevEco CLI 直接做成了可被 Agent 装载的 skill。

本机环境实测（只读）：Node v24.6.0 ✅、arm64 ✅、环境干净无残留；
**`/usr/bin/java` 是 stub，`java -version` 报 `Unable to locate a Java Runtime`，`java_home -V` 无任何 JVM**。

## 判断

- 「不装 DevEco Studio 也能创建并编译鸿蒙工程」从两说偏向成立，证据级别从「文档间接推断」升级为「包内实现」。
- 本机真实缺口收敛为**两个下载**：JDK 21 与 Command Line Tools ≥ 26.0.0（macOS ARM）。
- 发现 2 是本仓库存在价值的一个直接例证：**照官方文档抄的环境变量名会失败**，只有读包才能发现。
  这类「文档与实现不一致」应当在 `docs/` 里单独成节。
- 一个方法论收获：对有 `postinstall` 的包，`npm pack` + 解包审读是零风险的前置动作，
  而且往往比读文档信息量更大。建议固化为约定。

## 当日追加：工具链实装，上面两条 ⚠️ 已有答案

用户确认「我来装，走完整闭环」后执行。装的位置统一在 `~/.local/hmos-toolchain/`，
自成一体、不改 `~/.zshrc`、`rm -rf` 即卸载；环境变量收在 `harmony/env.sh` 里靠 `source` 生效。

### 实装结果

| 组件 | 结果 |
| --- | --- |
| DevEco CLI 1.3.0-stable（局部安装，非 `-g`） | ✅ `--version` 通过，16 个命令齐全，`postinstall` 无异常 |
| JDK 21（Temurin 21.0.12.1+1 LTS） | ✅ `java -version` / `javac -version` 通过，sha256 与 Adoptium 发布值逐字一致 |
| Command Line Tools ≥ 26.0.0 | ❌ 受阻，下载需华为账号 + **动态验证码** |

### 遗留问题的答案

- **「CLT 是否自带 JDK」→ 不自带。** 反编译 `dist/cli.js` 的 `resolveCltJava`：按
  `JAVA_HOME/bin` → `JAVA_HOME` → `PATH` 找 java，都没有则硬报错
  `No Java runtime found in CLT mode.`。所以 JDK 这个下载省不掉。
- **「`DEVECO_CLI_CLT_PATH` 在 macOS 上是否生效」→ 生效，且官方文档那个名字是错的。**
  这是本轮最硬的一个结论，靠对照实验拿到：

  | 设置的变量 | 实际输出 | 判读 |
  | --- | --- | --- |
  | `DEVECO_CLI_CLI_PATH`（官方文档写的） | `Error: DevEco Studio installation not found in default locations.` | 变量被完全忽略 |
  | `DEVECO_CLI_CLT_PATH`（包内 SKILL.md 写的） | `Error: Invalid DEVECO_CLI_CLT_PATH: /tmp/fake-clt` | 被读取并校验 ✅ |

  `dist/cli.js` 里 CLI 只认四个变量：`DEVECO_CLI_STUDIO_PATH` → `DEVECO_CLI_CLT_PATH` →
  `DEVECO_HOME` → `DEVECO_PATH`，**没有 `DEVECO_CLI_CLI_PATH`**。
  即：**照官方文档抄这一行环境变量，必然失败。**

  附带取到 CLT 的有效性判据：根目录须有 `version.txt`（`readCltVersion` 读它）。

### 新的硬卡点：CLT 下载必须人工登录

下载页与文档中心同为 SPA，`WebFetch` 只得空壳。第三方 CLI `chawyehsu/hdx`（专做华为下载中心）
的 `dget` 能解析直链，但 `auth login` 明确只支持「Huawei ID + 密码 + **动态验证码**」，
手机号/邮箱+密码都不行。动态验证码这一环 Agent 无法代办——**这不是技术问题，是账号问题。**

已把人要做的三步写进 `harmony/README.md`，判据收敛为一条命令：
`ls ~/.local/hmos-toolchain/command-line-tools/version.txt` 能看到文件即算就位。

### 自己踩的一个坑（记下来防再犯）

JDK 首次下载丢后台，只看文件大小（82 MB）就当完成并 `rm` 了 tar.gz，实际被截断，
解压报 `truncated gzip input: Unknown error: -1`，只能重下。
**教训：大文件必须校验 sha256，size 不算完成信号；后台任务要等通知或显式确认退出码。**
