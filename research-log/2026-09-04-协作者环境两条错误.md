# 2026-09-04 别人下载后打不开：两条平台配置错误

## 问题

代码推到 `origin/main` 之后，协作者在自己机器上先后报了两条错：

1. `Select an OpenHarmony or HarmonyOS project`
2. `The ArkTS SDK of version 23 in OpenHarmony is not found.[entry]`

要回答的是：各自的成因是什么，仓库该怎么改才能让别人下载后直接可用。

## 第一条：`Select an OpenHarmony or HarmonyOS project`

**成因是我自己的流程失误，不是工程结构问题。** 我上一轮把 33 个工程文件提交在
本地分支 `feat/openharmony-build-passing` 上就没再管，`origin/main` 停在 `09d6227`，
它的 `harmony/` 下只有 `README.md` 和 `env.sh`。核对方式：

```sh
git ls-tree -r --name-only origin/main | grep -c 'harmony/HybridShell'   # → 0
```

协作者下载到的确实是个没有工程的目录，IDE 报「请选择一个工程」完全正确。

⚠️ 我第一次回答把「打开的目录层级不对」排在最可能，**判断错了**，是用户提出
「是不是没提交代码」才查出真相。**教训**：交付给别人用的东西，要以远端内容为判据
（`git ls-tree origin/main`），不能以「我本地 commit 过了」为判据。

合并推送后（`09d6227..5df86bf`）远端已含全部 33 个文件，第一条消失。

## 第二条：`The ArkTS SDK of version 23 in OpenHarmony is not found.[entry]`

### 检索路径

先确认这句话是不是我这条链报出来的：

```sh
grep -rlo "ArkTS SDK of version" ~/.local/hmos-toolchain/clt-oh/     # 无匹配
grep -rho "SDK of version[^\"'\`]\{0,80\}" ~/.local/hmos-toolchain/clt-oh/   # 空
```

`clt-oh` 里唯一含 "ArkTS SDK." 的是一条无关的 Kit 配置报错
（`sdk/23/ets/build-tools/ets-loader/lib/process_kit_import.js` 的
`Kit '${t}' has no corresponding config file in ArkTS SDK.`）。
所以**这句不是本机 OpenHarmony 链发出的，来自协作者那侧的 HarmonyOS hvigor / DevEco Studio**。

### 原始发现：反向实验拿到镜像错误

把工程切回 HarmonyOS 配置（`runtimeOS: "HarmonyOS"` + `"6.1.0(23)"`），
用本机只有 OpenHarmony SDK 的链去编译：

```
> hvigor ERROR: 00303168 Configuration Error
Error Message: SDK component missing.
* Try the following:
  > Please verify the integrity of your SDK.
> hvigor ERROR: BUILD FAILED in 666 ms
hvigor sync failed
```

两条错误**互为镜像**：

| 工程写的 | 机器上有的 SDK | 报什么 |
| --- | --- | --- |
| `runtimeOS: "OpenHarmony"` + `23` | 只有 HarmonyOS SDK | `The ArkTS SDK of version 23 in OpenHarmony is not found.[entry]`（协作者侧） |
| `runtimeOS: "HarmonyOS"` + `"6.1.0(23)"` | 只有 OpenHarmony SDK | `00303168 SDK component missing`（本机实测，2026-09-04） |

### 判断

成因确定：`5df86bf` 提交的是**为了本机免登录编译而改过的 OpenHarmony 配置**
（`runtimeOS: "OpenHarmony"`、三个版本号是整数 `23`、多一个 `compileSdkVersion`、
`deviceTypes: ["default"]`）。协作者用 DevEco Studio for HarmonyOS，装的是 HarmonyOS SDK，
按 `runtimeOS` 去找 OpenHarmony 的 ets SDK，找不到。

这印证了 2026-09-03 记的那条边界：两套 SDK 家族靠元数据文件名硬性区分，**不能互相顶替**。
让协作者去装 OpenHarmony SDK 23（1,255 MB）不是好方案——DevEco Studio for HarmonyOS
是否提供该 SDK 也未确认（⚠️ 待核实）。

## 落点

新增 `harmony/switch-runtime.sh`，把两个文件四处值的切换收成一条命令：

```sh
bash harmony/switch-runtime.sh          # 看当前在哪一侧
bash harmony/switch-runtime.sh ohos     # 本机编译前切
bash harmony/switch-runtime.sh hos      # 提交前切回（仓库默认）
```

实现上把两个文件的平台相关行包进 `>>> PLATFORM BLOCK >>>` / `<<< PLATFORM BLOCK <<<`
标记，脚本只重写标记之间的内容（python3 正则，注释与其余配置原样保留）；
标记丢了就报错退出，而不是猜着改。

**仓库默认值改成 HarmonyOS 侧**（= `devecocli create` 的原值），这样别人 clone 下来
用 DevEco Studio 能直接打开。代价要说清楚：**入库那一份配置本身没被编译器验过**，
本机没有 HarmonyOS SDK；跑通 `BUILD SUCCESSFUL` 的是 `ohos` 那一侧。

两侧都实测过一遍：`ohos` → `BUILD SUCCESSFUL in 3 s 399 ms`；`hos` → `00303168`（预期失败）。

改的文件：`harmony/switch-runtime.sh`（新）、`harmony/HybridShell/build-profile.json5`、
`harmony/HybridShell/entry/src/main/module.json5`、`harmony/README.md`（文首加平台配置一节、
`modelVersion` 归因修正）。

## 遗留

- ⚠️ DevEco Studio for HarmonyOS 能否装 OpenHarmony SDK 23，未确认。
- ⚠️ 协作者侧的 HarmonyOS 配置能否真编过，本机验不了（无 HarmonyOS SDK），要等他们回报。
- 一个工程要伺候两套 SDK 终究是权宜。真 CLT 到位后应当只留 HarmonyOS 一侧，
  `switch-runtime.sh` 届时可以删。
- `modelVersion` 的准确说法：模板磁盘上是 `6.0.2`，`create` 落盘替换为 `6.1.0`。
